# 환경계획 통합 모니터링 대시보드

EU JRC의 [EU BDS Actions Tracker](https://dopa.jrc.ec.europa.eu/kcbd/actions-tracker/)와
[EU BDS 2030 Dashboard](https://dopa.jrc.ec.europa.eu/kcbd/EUBDS2030-dashboard/)를 참고해 만든
**지표 대시보드 + 이행과제 트래커 + 관리자 페이지** 통합 앱입니다.

**모니터링 영역 3개**로 나뉩니다.

| 영역 | 주소 | 내용 |
|---|---|---|
| 계획이행 모니터링 | `/plan` | 계획의 목표·세부목표별 이행 상황 (K-SDGs 13·14·15 기반 샘플) |
| 환경상태 모니터링 | `/state` | 대기·물·생활/자연환경의 실제 관측치 |
| 환경체감 모니터링 | `/perception` | 시민 만족도·불편 경험·인식 조사 결과 |

영역은 DB에서 오므로 관리자에서 추가하면 **상단 메뉴와 주소가 자동으로 늘어납니다.**
나중에 자체 환경계획 지표로 **코드 수정 없이** 전환할 수 있게 설계되어 있습니다.

---

## 빠른 시작

```bash
npm install
npm run db:push     # SQLite 스키마 생성 (prisma/dev.db)
npm run db:seed     # sheets/*.csv 를 초기 데이터로 주입
npm run dev         # http://localhost:3000
```

관리자 로그인: `http://localhost:3000/admin` → 비밀번호는 `.env`의 `ADMIN_PASSWORD` (기본값 `admin1234`).

> **배포 전 반드시** `.env`의 `ADMIN_PASSWORD`와 `SESSION_SECRET`을 바꾸세요.
> `SESSION_SECRET`은 `openssl rand -hex 32` 등으로 긴 랜덤 문자열을 넣으면 됩니다.

### 운영 실행

```bash
npm run build
npm run start       # 기본 3000 포트, PORT=8080 npm run start 처럼 변경 가능
```

## 달성도 계산 규칙

`src/lib/progress.ts` 한 곳에서 관리합니다.

```
진행률(%)   = (최신값 − 기준값) ÷ (목표값 − 기준값) × 100
기대진행률(%) = (최신 데이터 연도 − 기준연도) ÷ (목표연도 − 기준연도) × 100
```

- 분모의 부호가 증가·감소 방향을 흡수하므로 **온실가스 배출량처럼 값이 작아져야 좋은 지표도 같은 식**으로 계산됩니다.
- 기대진행률은 현재연도가 아니라 **최신 데이터 연도** 기준입니다. 통계 공표가 1~2년 늦는 지표를 현재연도 기대치와
  비교하면 정상 지표까지 「지연」으로 찍히기 때문입니다.

| 상태 | 조건 |
|---|---|
| 달성 | 진행률 ≥ 100% |
| 순조 | 진행률 ≥ 기대진행률 × 0.9 |
| 지연 | 진행률 < 기대진행률 × 0.9 |
| 악화 | 진행률 < 0 (기준값보다 후퇴) |
| 모니터링 | 목표값 미설정 |
| 자료없음 | 실적값 없음 |

최신 자료가 3년 넘게 갱신되지 않으면 「자료 갱신 필요」 배지가 함께 붙습니다.
`status_override`(관리자 화면의 "상태 직접 지정")를 채우면 자동 판정 대신 그 값을 씁니다.

## 확장성 — 행만 추가하면 알아서 늘어난다

코드에 `13`, `14`, `15`나 목표 개수·지표 개수가 **하드코딩되어 있지 않습니다.**

- 관리자에서 **영역**을 추가 → 상단 메뉴와 `/새코드` 주소가 자동 생성됩니다.
- 관리자에서 목표를 4번째로 추가 → 개요에 카드가 하나 더 생기고, 필터 항목이 늘고, 색을 비워두면
  `src/lib/colors.ts`의 팔레트에서 자동 배정, 그리드는 `auto-fit`이라 알아서 재배치됩니다.
- 실적값 연도를 추가 → 최신값·추세·진행률·차트 X축이 자동 갱신됩니다.
- 계층 명칭은 `/admin/config`의 `level0_label` ~ `level3_label`에서 주입되므로,
  「모니터링 영역/목표/세부목표/지표」를 「분야/부문/추진전략/계획지표」로 바꾸면 **화면 전체 용어가 한 번에 바뀝니다.**

즉 **자체 환경계획 지표로의 전환은 "관리자에서 내용 갈아끼우기"만으로 끝납니다.**

## 색상 시스템

두 층으로 분리되어 있습니다 (`src/lib/colors.ts`, `src/lib/progress.ts`).

- **목표별 아이덴티티 컬러** — 다양성 담당. 목표에 색 하나만 지정하면 HSL로 분해해 배경 tint / 보더 /
  텍스트 / 그라디언트 끝색 / 반투명 오버레이가 자동 파생되고, 헤더 그라디언트·도넛·차트·카드 액센트 바·
  필터 칩에 전부 전파됩니다. 색을 비우면 팔레트에서 자동 배정됩니다.
- **상태 컬러** — 일관성 담당. 달성/순조/지연/악화/모니터링/자료없음은 전 화면에서 같은 색이며,
  색맹 대비로 아이콘과 텍스트를 함께 표기합니다.

## CSV 가져오기 · 내보내기

`/admin/data`에서 7종(모니터링 영역·목표·세부목표·지표·실적값·이행과제·설정)을 CSV로 주고받습니다.

- 내려받은 CSV는 **그대로 다시 올릴 수 있는 형식**입니다. 엑셀에서 고쳐 다시 올리면 됩니다.
- 구글시트·엑셀에서 표를 복사해 **붙여넣기 칸에 그대로 붙여넣어도** 인식합니다(탭 구분 자동 감지).
- 고유번호(`track_id`, `goal_id`, `target_id`, `indicator_id`, `action_id`) 기준으로 **있으면 수정, 없으면 추가**합니다.
- 전체를 처음부터 넣을 때는 영역 → 목표 → 세부목표 → 지표 → 실적값 → 이행과제 → 설정 순서로 올려야 참조가 연결됩니다.
- 공개 화면의 영역별 내려받기는 `/api/export?type=indicators&track=<코드>` 형태로 필터됩니다.
- 컬럼 형식은 `/admin/data` 하단과 `sheets/README.md`에 정리되어 있습니다.

초기 시드 데이터는 `sheets/*.csv`에 있으며 `npm run db:seed`로 다시 주입할 수 있습니다.
(주의: 시드는 **기존 데이터를 모두 지우고** 다시 채웁니다.)

## 기술 구성

- **Next.js 15** (App Router) + React 19 + TypeScript
- **Tailwind CSS v4** + **shadcn/ui**
- **Prisma 6 + SQLite** — DB는 `prisma/dev.db` 파일 하나
- **Recharts** — 시계열 차트
- 인증: 공용 비밀번호 + HMAC 서명 세션 쿠키(httpOnly, 12시간)
- 모든 쓰기는 **서버 액션**을 통하며, 각 액션은 `requireAdmin()`으로 보호되고 `AuditLog`에 기록됩니다.

```
src/
├─ app/
│  ├─ (public)/           # 공개 대시보드 (개요·지표·이행과제·데이터)
│  ├─ admin/              # 관리자 화면
│  ├─ api/export/         # CSV 내려받기
│  └─ login/
├─ components/
│  ├─ ui/                 # shadcn/ui
│  ├─ admin/              # 관리자 전용 폼 유틸
│  └─ *.tsx               # 카드·차트·필터 등 공용 컴포넌트
└─ lib/
   ├─ progress.ts         # 달성도·상태 판정  ← 규칙 변경은 여기 한 곳
   ├─ colors.ts           # 목표색 팔레트·톤 파생
   ├─ data.ts             # 대시보드 데이터 조회·조립
   ├─ csv.ts              # CSV 내보내기 스키마
   ├─ admin-actions.ts    # 서버 액션(CRUD·가져오기)
   └─ auth.ts             # 세션
```

### Node 버전 안내 (다른 곳에 복사할 때 꼭 읽어보세요)

**Node 20 이상을 권장합니다.** Tailwind v4의 네이티브 모듈(`@tailwindcss/oxide`)이 Node 20+를 요구하는데,
npm은 engines 조건이 안 맞는 optional 의존성을 조용히 건너뜁니다. 그러면 빌드할 때 이런 오류가 납니다.

```
Error: Cannot find native binding.
```

- **Node 20 이상** → 그냥 `npm install` 하면 됩니다. 아래 내용 무시하세요.
- **Node 18 + Linux x64** → `npm install` 후 한 번만 `npm run fix:node18` 을 실행하세요.
- Mac/Windows에서 Node 18을 쓴다면 자기 플랫폼 패키지(`@tailwindcss/oxide-darwin-arm64` 등)를
  같은 방식으로 `--force`로 설치하거나, Node를 20 이상으로 올리세요.

`@tailwindcss/oxide-linux-x64-gnu`는 `optionalDependencies`에 있어서, 다른 플랫폼에서 `npm install`이
실패하지 않고 그냥 건너뜁니다.

### 개발 중 주의

**dev 서버를 켜둔 채로 `npm run build`를 실행하지 마세요.** 둘 다 같은 `.next` 폴더를 쓰기 때문에
실행 중인 dev 서버가 `MODULE_NOT_FOUND`로 깨집니다. 그런 상황이 되면 `.next`를 지우고 다시 시작하면 됩니다.

```bash
rm -rf .next && npm run dev
```
